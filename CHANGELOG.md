# Changelog

All notable changes to Peak Code are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.8.1] - 2026-09-22

### Fixed

- **A custom provider named after a built-in no longer takes that built-in's row.** 0.8.0 derived a new provider's key from its display name, which put the built-in template ids back in reach: a key that matches a template _is_ that template as far as the rail is concerned (that is how its custom group filters them out), so adding a provider called "StepFun 自建" derived `stepfun` — 阶跃星辰 StepFun's own id — and the provider disappeared into that built-in row with its endpoint, key and model list, never appearing as a custom provider at all. The reserved `custom` stand-in was the same trap one step over. The derivation now steps around the reserved keys and the ones already configured, and the hint under the name field and the save use the same derivation, so the key it promises cannot differ from the key it writes. ([apps/web/src/components/ModelProvidersSettingsPanel.tsx](apps/web/src/components/ModelProvidersSettingsPanel.tsx))
- Two browser tests were still filling a "Provider key" field the create form no longer has, so `bun run test:browser` failed in CI on a change whose local runs were all unit-suite runs. They assert the field is gone and that the key comes from the name, and a new one covers the collision itself.

## [0.8.0] - 2026-09-22

### Added

- **Multi-Agent — a turn that splits its work across named workers.** The fourth interaction mode delegates instead of working through the request itself: the orchestrator breaks the task down, dispatches one worker per part through the `task` tool, and merges what comes back into a single answer. A worker is a registry entry rather than a prompt — handle, description, extra instructions, tool allowlist and **its own model** — so one turn can keep its planner and merger on a strong model while the file-grepping workers run cheap, which is the whole point of the feature. Three ship with the app (`explore` read-only, `general` full tool set, `review` uncommitted changes), Settings → 子智能体 adds and edits the rest, and a registry the user emptied is a legitimate state (saved as `[]`) rather than an invitation to restore the defaults. ([packages/agent-toolkit/src/agent-subagents.ts](packages/agent-toolkit/src/agent-subagents.ts))
- **The split is explained before it is spent.** A protocol step saying "analyse first, then delegate" turned out to be advice a model can ignore: a user message was answered by a run of `task` calls, and a fan of sub-agents appeared with nothing on screen explaining it. A turn's first `task` call is now refused once until that turn has written visible text (thinking does not count), with the refusal itself carrying the reason. The gate re-arms per request — `before_agent_start`, once per `prompt()` — not per model round, so delegating in an earlier turn does not exempt the next message and the worst case is one extra round rather than a turn that can never delegate again. ([apps/server/src/agentToolkitMode.ts](apps/server/src/agentToolkitMode.ts))
- **Delegation is readable while it runs.** A dispatch draws a card in the transcript: the orchestrator on one side, each worker on a branch off it, with its model, its state (hue, icon and, while it is out, motion — colour alone cannot say "still working" to everyone), the steps it has taken, the tool call running right now and how long it has been out. A row opens that worker's own thread with the full tool log. The progress travels on the delegation item itself (`agentStates[].steps / lastStep / lastStepAt / startedAt`, counted per distinct tool call and republished on a 2-second throttle) instead of only through the worker's child thread. ([apps/web/src/components/chat/SubagentDelegationCard.tsx](apps/web/src/components/chat/SubagentDelegationCard.tsx))
- **One worker can be stopped without killing the turn.** A worker 38 minutes into a broad search left two options: end the whole turn — losing the orchestrator's context and every other worker's result — or wait. Each running worker now carries **Stop**: `ProviderStopSubagentInput` → `WS_METHODS.subAgentsStopRun` → `ProviderService.stopSubagent` → `PiAdapter.stopSubagent`, routed by delegation id (the `providerThreadId` the card already publishes) rather than by child thread id, since that is the key the runtime registry is built on. The card is settled to `stopped` before the abort is issued, for the same reason the stall watchdog settles first: an abort that never returns must not leave the card claiming work. It returns a boolean — `false` means nothing was running under that id, not a failure, so the UI does not raise an error for a worker that had already finished — and the orchestrator and the remaining workers carry on, with the early ending handed back to the model as a gap. ([apps/server/src/provider/Layers/PiAdapter.ts](apps/server/src/provider/Layers/PiAdapter.ts))
- **An About section, and one update flow behind both entry points.** Settings → 关于 holds the app identity, the version, the desktop update action (check / download / install with the pending release's notes and the changelog) and the outbound links; the sidebar's compact update button drives the same state machine through `useDesktopUpdate`, so the two cannot show different states or wording, and a state flush runs before the app quits to install. ([apps/web/src/components/AboutSettingsPanel.tsx](apps/web/src/components/AboutSettingsPanel.tsx))

### Changed

- **Multi-Agent delegates through `task` only.** The mode also exposed pi-crew's whole `crew_*` tool set, and a model picking between two delegation paths at random meant work that was invisible in the UI and impossible to stop. The `crew_`-prefixed tools are withheld in Multi-Agent mode (matched by prefix, not enumerated by name), leaving the one path that has per-worker models, cards, child threads and a stop button. Other modes still get pi-crew. ([apps/server/src/agentToolkitMode.ts](apps/server/src/agentToolkitMode.ts))
- **Adding a provider no longer asks for a "provider key".** The free-text key field invited pasting the API key into it, which then became the provider's id and put the secret in `models.json`. The id is derived from the display name (with a short hash for names that have no ASCII letters, so several all-Chinese names cannot collapse onto one key, and a numeric suffix when it collides), and the create form's model picker now runs before the provider exists on disk: the form's unsaved Base URL, API type, auth header and key win over the saved config field by field, and a key typed into the field outranks the stored credential. ([apps/web/src/lib/modelProviderDraft.ts](apps/web/src/lib/modelProviderDraft.ts), [apps/server/src/modelProviderConnection.ts](apps/server/src/modelProviderConnection.ts))

### Fixed

- **A working worker is no longer settled as an orphan by the reaper.** The recovery sweep asked every thread the same question — is a live provider session running this turn — and a worker's session is created inside the adapter (`runSubagent`), invisible to the provider directory, so for every child thread the answer was forever "no" and each 5-minute sweep settled _actively working_ workers as interrupted. The evidence is exact: three child sessions flipped at 08:15:16, the sweep an hour after the 07:15:16 start, while their activity kept arriving past 08:29 — and the card said `Idle` while the thread said interrupted and the work went on. A child thread is now settled by its parent: while the parent is running the turn its workers are its business, and when the parent is settled the children settle in the same sweep. A worker can no longer outlive the turn that dispatched it. ([apps/server/src/orchestration/abandonedTurn.ts](apps/server/src/orchestration/abandonedTurn.ts), [apps/server/src/provider/Layers/ProviderSessionReaper.ts](apps/server/src/provider/Layers/ProviderSessionReaper.ts))
- **A worker's state is no longer overwritten by a staler source.** `deriveSubagentStatus` answers `Idle` for a child-thread session that is not live, and that answer outranked the delegation's own `running` — so "still working" was written on screen as `Idle`. The delegation now decides the state and the thread may only add detail; `startedAt` supplies the elapsed time as a fallback, so a worker with no steps counted yet still shows how long it has been out instead of nothing. ([apps/web/src/lib/subagentProgress.ts](apps/web/src/lib/subagentProgress.ts))
- **A freshly dispatched worker no longer wears the previous dispatch's numbers.** `subagentAgentId` is a worker handle (`explore`), not a run identity, so the second dispatch of the same worker produces a child thread indistinguishable from the first, and the fallback match took "the first candidate": a just-dispatched worker showed the _previous_ turn's steps, duration, last step and `Idle` (117 steps on screen as 55 / 6m53s / a last step 21 minutes old). A candidate is now accepted only when it is unique; an ambiguous match shows nothing rather than something wrong. ([apps/web/src/components/ChatView.logic.ts](apps/web/src/components/ChatView.logic.ts))

## [0.7.2] - 2026-09-21

### Fixed

- **Stopping a turn ends it, whatever state the provider is in.** A stop is only a request, and the path behind it could not tell "the provider is running this" from "nothing is running this any more": with no live session it _recovered_ one — a fresh runtime, freshly loaded extensions — and then aborted that, reporting success while the turn it had been asked to stop was already over and leaving the thread on screen as running. A real thread shows what that costs: the provider process exited eight seconds after the turn's last event, five stop clicks two hours later changed nothing at all, and only the ten-minute idle timer on the recovered session eventually cleared it. An interrupt for a thread with no live provider session now closes that turn as interrupted and says so in the thread, `ProviderService.interruptTurn` no longer recovers a session it can only abort, and `ProviderService.abandonTurn` makes stopping unconditional — when the provider accepts the request and never settles the run, the runtime is freed instead (the persisted resume cursor survives, so the next message continues the conversation rather than steering into a run nobody can stop). ([apps/server/src/provider/Layers/ProviderService.ts](apps/server/src/provider/Layers/ProviderService.ts), [apps/server/src/orchestration/Layers/ProviderCommandReactor.ts](apps/server/src/orchestration/Layers/ProviderCommandReactor.ts))
- **A turn that has stopped progressing ends itself.** Nothing bounded a provider request that opens a stream and then goes quiet. Pi's own request timeouts do not cover a stream that stops talking, and a run parked there emits no `turn.completed`, so the thread reads as running indefinitely with a spinner and no way to tell whether any work is happening — the same screen a killed process leaves behind, without the restart that eventually reveals it. A turn with no provider event for 30 minutes is now failed and its runtime released, reported the way a real failure is: the thread leaves "running", the reason is kept as the thread's error, and anything waiting on the turn's outcome stops waiting. The window is deliberately generous — approvals and `ask_user` wait ten minutes and announce themselves, the toolkit caps a shell command at two, and pi's own bash tool has no cap at all — and it is `PEAKCODE_PROVIDER_TURN_STALL_MS`-tunable, `0` to disable. ([apps/server/src/provider/Layers/ProviderService.ts](apps/server/src/provider/Layers/ProviderService.ts))
- **A restart can no longer leave a thread running forever.** The projection persisted "turn running" while the process that owned the turn was gone, and the session reaper skipped exactly those threads (`activeTurnId` set), so a killed turn stayed on screen for hours with a live timer and every later stop had nothing to abort. The reaper now settles a turn the projection still claims when no provider session is running it — at its first sweep, which is what a boot after a crash leaves behind, without waiting for a click. Its stale-session cleanup also stops the runtime (`stopRuntimeSession`) instead of deleting the persisted binding, because deleting the binding also threw away the provider resume cursor that continues the thread's conversation. ([apps/server/src/provider/Layers/ProviderSessionReaper.ts](apps/server/src/provider/Layers/ProviderSessionReaper.ts))
- A turn's own dispatcher reads an abandoned turn — a session set to `interrupted` with no active turn — as an outcome, so an automation, a kanban card or the IM bridge stops waiting for a conclusion that is never coming. ([apps/server/src/orchestration/turnOutcome.ts](apps/server/src/orchestration/turnOutcome.ts))

## [0.7.1] - 2026-09-20

### Fixed

- **Typed input is no longer dropped by leaving a screen.** The 0.7.0 fix below stopped a _provider or model_ from vanishing; this closes the same hole everywhere else it existed. In Settings → 模型提供商 a field (显示名称 / Base URL / API Key) is now written out when it is left rather than only through a save bar below the card, the API-type picker and 清除已保存的密钥 save on the spot, and a draft that is still dirty as the panel unmounts — a keystroke that never blurred, or a save that failed — is written out on the way. The save bar stays as the retry button after a failed save, and the form is no longer disabled while a save is in flight, which used to steal focus from the field you had just moved to. In Settings → 频道 each card keeps its own unsaved secrets, so opening a second channel no longer wipes the first one (the button that opens a card said 保存 although it was not the save action — it says 编辑 now), and the 远程访问 path commits when it is left. Leaving either section with something typed but unsaved asks first.
- **A kanban task's own form survives the board's poll.** The detail page re-seeded its title/status/priority/agent from every poll, so a comment landing on the card — the agent working while you edit — reverted what you were typing. An untouched form still follows the board; one holding an edit is left alone. Leaving the page with an unsaved edit (the Back button, the sidebar, a keyboard jump) now asks, the way the task create page already did.
- **Closing an editor by accident asks before discarding what is in it.** A click on the backdrop, Escape or the X used to throw away a whole automation (title plus instructions), a model definition, or an action's name/command line/keybinding with no warning, and a colour changed in the last 220 ms before the appearance editor unmounted was dropped by the timer that was meant to commit it. Each of those now commits or confirms; a documented Cancel or an untouched form still closes immediately.
- **The phone keeps a half-written reply.** Leaving a conversation for the task list — or opening another task — unmounted the reply box and lost the text; the draft now lives per conversation and comes back with it. A workspace rename committed on blur or Enter is likewise kept when the page unmounts first, which is what a keyboard navigation with the field still focused used to lose.
- The "would you lose this?" question is one place now: `useUnsavedChangesGuard` covers route changes and reload for a screen that holds unsaved input, and the kanban create page uses it instead of its own copy of that logic. ([apps/web/src/hooks/useUnsavedChangesGuard.ts](apps/web/src/hooks/useUnsavedChangesGuard.ts))

## [0.7.0] - 2026-09-20

### Added

- **A provider's API key is kept in Pi's credential store instead of `models.json`.** The config file is configuration: it is read, copied between machines and edited by hand, so a literal key typed in Settings → 模型提供商 is no longer written into it. Saving moves such a value to `<agentDir>/auth.json` as an `api_key` credential, and the panel then reports the key as saved without echoing it back — an empty key field means "keep the stored one", and 清除已保存的密钥 is the explicit way to drop it. `$ENV_VAR`, `${ENV_VAR}` and `!command` are configuration rather than secrets and stay in the file, and because a stored credential outranks a configured key the two are kept mutually exclusive: saving a reference clears the stored key instead of leaving an edit that appears to do nothing. A literal key already sitting in `models.json` is migrated the next time that provider is saved, every other entry in `auth.json` (OAuth logins, other providers) is carried through untouched, a provider removed from the rail gives up its stored key so re-adding it cannot silently authenticate with the old secret, and a save that moves no key leaves the file alone rather than rewriting — or creating — it. ([apps/server/src/providerCredentials.ts](apps/server/src/providerCredentials.ts))
- **A saved provider edit reaches a running session on the next turn, without a restart.** A Pi model runtime composes its providers once — base URL, key, model list — so a session that had already started kept talking to the superseded endpoint with the superseded key, and failed with an authentication error that re-configuring the key could not clear. The runtime for an agent dir is now handed out through a revision check over both files that decide what it can authenticate against (`models.json` and `auth.json`, identity = modification time plus size, a missing file being a revision of its own), so a save is noticed and the configuration re-read before the runtime is used again; the catalogue re-read is deliberately offline, so the panel's next turn never depends on a network round trip succeeding. ([apps/server/src/provider/modelRuntimeCache.ts](apps/server/src/provider/modelRuntimeCache.ts))
- **Settings → 使用统计 gives Peak Code its own row instead of burying it inside Pi's.** This app runs Pi, so its transcripts would otherwise be counted under Pi — including another app's, since they share a `sessions` root. The same archive is now read once and split: a transcript counts as Peak Code's when it is one of the resume cursors this app recorded for its own threads (it spawned it, even if the project was later deleted) or when the workspace in its `session` header is exactly one of the app's project roots or inside its managed worktrees directory; everything else Pi recorded stays on the Pi row, and the two rows always sum back to the machine total. The tool breakdown pins this app first and ranks the rest by tokens. ([.docs/usage-statistics.md](.docs/usage-statistics.md))

### Fixed

- **A provider or a model added under Settings → 模型提供商 is written to `models.json` as soon as it is added.** Adding one only staged it in the panel's draft, and that draft is discarded when you leave the settings screen: configure a provider, add a model to it, go back to the chat — the chat still offered the models from before, and returning to the panel showed the provider gone, because nothing had ever reached the file. Adding, editing or removing a provider or model, and importing ids from the provider's own `/models` list, now save immediately, the same write-then-act shape 启用 and 测试连接 already had; free-text edits (name, Base URL, the key field) still wait for 保存更改, whose 未保存的更改 hint keeps saying so. ([apps/web/src/components/ModelProvidersSettingsPanel.tsx](apps/web/src/components/ModelProvidersSettingsPanel.tsx))
- **Stopping a turn that is parked on an approval prompt or an `ask_user` question lands immediately.** Pi awaits both gates directly and neither is raced against the run's abort signal, so `abort()` waits for a run that cannot go idle until its gate is answered — and the orchestrator interrupts on its serial worker, so that wait also stalled every later command for the thread until the ten-minute request timeout. The gates are now answered as cancelled before the abort, and an interrupt the provider does not acknowledge within 15 seconds is reported in the thread (with the turn left to end on its own) instead of holding the worker.

## [0.6.0] - 2026-09-18

### Added

- **Settings → 模型提供商 can import a provider's own model list.** A 获取模型列表 action next to 添加模型 calls the provider's `/models` endpoint and opens a picker over what it returned: a search box, category chips (对话 / 嵌入 / 重排 / 语音合成 / 语音识别 / 图像 / 视频 / 音乐 / 其他, counted and shown only for the families that provider actually returned), and the ids grouped by the vendor prefix before the slash, each with its own add control plus 添加本组 and 全部添加. Picked ids are added as bare `{ id }` entries — pi fills in the rest — and land in the draft, so they save with the rest of the panel. The request runs on the server (`server.listProviderModels`) rather than in the browser, because the credential has to be resolved through pi's own auth: an `ENV_VAR` reference or a `!shell` command in `apiKey` must reach the endpoint as its real value, and a renderer fetch would also meet CORS. The endpoint comes from the saved `baseUrl` — a base that already carries a version segment (`/v1`, `/v4`, `/v1beta/openai`) is only suffixed with `/models`, while a bare host tries `<base>/models` then `<base>/v1/models` — the auth header follows the API kind (`Authorization: Bearer` by default, `x-api-key` + `anthropic-version` for `anthropic-messages`, none for a provider with `authHeader: false`), and the parse accepts the array, `data` and `models` shapes plus Google's `{ name: "models/…" }`, deduping what it finds. Failures say what to do about them — a web page at the address ("point Base URL at the API root"), a rejected key, an upstream message — instead of a JSON parse error, and the fetch gives up after 15 seconds. The category classifier is a port of OmniStudio's name heuristic, ordered strictest-family-first so that `bge-reranker-v2-m3` is a reranker and not an embedding. ([apps/web/src/lib/modelCategories.ts](apps/web/src/lib/modelCategories.ts))
- **The provider rail lists candidates you enable, not only what you already wrote.** Every template is listed whether or not it is in `models.json`, grey-dotted until it is enabled; selecting one shows an 启用 form carrying the template's endpoint and API type, and enabling it writes the provider plus your key to the file and immediately runs a real connection test against its first model. Un-enabled templates are never written to `models.json`, and the enable flow is deliberately save-then-test rather than test-then-save, because the test resolves the credential the way a session does. 小米（MiMo） replaces 零一万物 01.AI (`https://api.xiaomimimo.com/v1`, OpenAI-compatible), the Chinese vendors now lead the list with DeepSeek at the top, and the China / Global / Local prefixes are gone from both the rail and the template picker.

### Changed

- **测试连接 is clickable at any time.** It used to be disabled whenever the draft had unsaved edits — which is exactly the state you are in after pasting a key — so the button now saves the pending edits first and tests what it just wrote, and the hint under the model list says so.
- The custom-provider form asks for the API key last: 名称 → 提供商 Key → Base URL → API Key, instead of a key field appearing before the provider has been described at all.

### Removed

- Settings → 高级 → 关于 → 更新历史 and the release-history dialog behind it, along with its strings (including a `releaseHistory` namespace nothing referenced) and the "📚 Release history in Settings" changelog entry that pointed users at it. The post-update What's New dialog and its own "Complete changelog" screen are untouched.

## [0.5.0] - 2026-09-18

### Added

- **The sidebar can browse the workspace as files now, not as a flat attachment list.** A workspace tree (built from the thread's root, ".") sits in the sidebar with folders and files you can expand, a search over the tree filters by name, and opening a text file shows it in a large file viewer with line numbers and monospace text, while binary or oversized files are handled gracefully instead of rendered. The tree is a real revision of the workspace: `workspaceChangedFiles` works out which files each turn actually touched (created, modified, deleted) so a run's footprint is visible as a 已变更 list, and `workspaceRevision`/`workspaceFileContent` serve the per-turn diffs and file bytes the viewer reads over WebSocket. The whole surface is off unless the thread has a workspace. ([.docs/workspace-file-explorer.md](.docs/workspace-file-explorer.md))
- **Settings → 使用统计 is a local token ledger for the whole machine, not just for this app.** It reads every coding agent's own session records on this machine — Peak Code itself, Claude Code, ccmr, Codex, ZCode, WorkBuddy, Pi, OpenCode, Grok Build and DeepSeek Harness — and reports 累计/峰值 Token 数, 最长聊天时长, 当前/最长连续天数, a year of activity as a calendar heatmap (每日/每周/累计), a per-model daily trend over 近 7 日 / 近 30 日, the model split as a donut, a per-tool breakdown with each tool's share and where its logs were looked for, the input/output/cache split of the same total, and a session drill-down down to numbered individual requests. Nothing is uploaded and nothing is written to the app database: the app's own SQLite projection stores only cumulative session snapshots and retention deletes them a week after a thread goes quiet, so local logs are the source of truth. One convention is enforced across all nine formats before anything is summed — `inputTokens` excludes cache reads (Anthropic-shaped logs already report it that way, OpenAI-shaped logs roll the cache into `input`, so those subtract it out), cache read/write are counted separately, and reasoning is recorded but never added because Pi and OpenCode already count it inside `output`. The per-tool quirks that would silently corrupt the total are handled explicitly: Claude Code writes one line per assistant content block and only the last line carries `output_tokens`, so records merge by message id keeping the largest output; Codex reports either exact per-turn usage or a cumulative counter that has to be differenced per file (summing the totals counts a resumed session up to nine times over); WorkBuddy attaches usage to whichever record carried the request and keeps the real model name in `providerData.model`. Records are read from the last 400 days, folded as they are read (a heavy machine logs requests by the million — this one has 61k across six tools) so memory stays bounded, with the request logs of only the most recently active sessions retained for drill-down. Peak Code leads the list as its own row rather than being buried inside Pi: the same archive is read once and split, so a Pi session counts as Peak Code's when its transcript is one of the resume cursors the app recorded for its own threads (it spawned it, even if the project was later deleted) or when the workspace in its `session` header is exactly one of the app's project roots or inside its managed worktrees directory — everything else Pi recorded, including another app that embeds Pi, stays on the Pi row, and the two rows always sum back to the machine total. Tools that were never used are still listed, marked 未检测到记录 with the path searched, because "installed but unused" and "not installed" are different answers. The tool breakdown pins this app first and ranks the rest by tokens. Two RPCs: `server.getUsageStatistics` (`{ source?, windowDays?, refresh? }`, cached 30s with a per-file cache so filtering costs milliseconds) and `server.getUsageSessionDetail` (`{ source, sessionId }`). No cost estimates — the logs barely carry price data — and no quota or balance polling, which would mean calling provider APIs with the user's credentials. ([.docs/usage-statistics.md](.docs/usage-statistics.md))

## [0.4.0] - 2026-09-18

### Added

- **The agent can use this Mac**: the `computer` tool drives native apps the way a person does. `get_state` reads the accessibility tree of the app in front — each control's role, name, position, size and the actions it actually supports, with a ref to act on — and `act` presses, focuses, raises or writes a value on that ref without moving your pointer or taking your focus. `click`/`type`/`key` post real input for the targets a tree cannot express (a canvas, a custom-drawn control) and say so, because they do move the cursor and type into your focus. A `screenshot` comes back as an image with the display's scale already accounted for, so the point you read off the picture goes straight into `click`. Observation is bounded twice so a wedged app cannot hang the socket, element actions through the accessibility API are preferred over coordinates, and a ref from an older observation is refused with an explanation rather than quietly landing on whatever now sits at that position. The work runs in a native helper of its own — a small **Peak Code Computer Use** app, which is what macOS files the Accessibility and Screen Recording grants against rather than Peak Code itself — installed at a fixed path, launched through LaunchServices, and rebuilt only when its own source changes, so those two switches in System Settings are a once-per-machine decision that survives every rebuild. A packaged build ships the helper in `Contents/Resources/computer-use`; a checkout compiles it on first launch; either way the installed bundle is fingerprinted and left untouched when it is already current. When a permission is missing, the model is told exactly which one and to stop until the user grants it. The same tool moves through a window the way a person does — `scroll` with a direction and a distance, `drag` as one gesture along a path (a slider, a reorder, a selection, a canvas) with modifiers if the gesture needs them, and `click` with double and right-button forms — and the clipboard is part of the desktop rather than a secret behind `type`: `read_clipboard` gets what the user or an app just copied, `write_clipboard` hands text to an app that wants a paste, and `type` can take `strategy: \"paste\"` to enter long text or CJK as one ⌘V instead of hundreds of keystrokes (the user's clipboard is put back afterwards). `list_windows` reports every on-screen window with bounds a click can be aimed at, `displays` reports the displays and their scale factors, and coordinates are handled properly on both counts: a capture carries where it started on screen and the scale of the display it is on, so a point read off a screenshot of a window on a second monitor lands where it looks like it should — the earlier code divided by the main display's scale and ignored the capture's origin, which put clicks off by the window's distance from the screen's corner. The helper now answers a bug in one of its own handlers with an `internal_error` that names it instead of taking the process down with it. macOS only. ([.docs/computer-use.md](.docs/computer-use.md))

- **Plugins attach to a turn, several at a time.** A plugin card in `/plugins` — or one of the installed tiles — opens a detail view (long description, capabilities, the skills it ships, example prompts) whose **Use plugin** / **立即使用** action puts the plugin on the composer of the chat you were last in, opening a new chat when there is none. The composer's `+` menu lists the discovered plugins too, as checkboxes, so one turn can carry more than one, and each shows up as a removable chip. Chips live on the composer draft next to images, pasted screenshots and assistant selections — attaching a plugin never costs you an attachment — and the turn carries them as `mentions` exactly the way an `@name` token does, deduped so a plugin both named in the prompt and picked as a chip is sent once. ([.docs/bundled-plugins.md](.docs/bundled-plugins.md))

- **IM channels**: a message sent from a chat app opens (or continues) a thread in the workspace and the answer is sent back into the chat, so the run stays a conversation you can open and continue in the app. Six channel ids: personal **WeChat** (a QR handshake mints its credentials, then a bridge long-polls outward, so no public URL is needed), **Feishu/Lark** and **QQ** over their own outbound sockets, **企业微信** and **微信公众号** as signed Tencent callbacks (those two need public HTTPS), and a generic **webhook** that carries both directions — the push-only group robots that announce a finished run and the secret-guarded inbound bridge. The bridge keeps its conversation index in SQLite (migration `042_ImConversations`), starts a fresh thread after `sessionIdleHours` idle (default 12, `0` = never), resolves workspace and model per turn because an IM run has no composer, queues a message that arrives mid-turn, and withdraws the channel's own "working on it" notice once the answer lands. Config and status traffic is owner-only — these endpoints can mint a pairing link — while the Tencent callbacks authenticate by signature and `POST /api/im/task` by its own secret, which is mandatory as soon as the server is reachable beyond loopback. Settings → 频道 renders the whole surface: per-channel status, the callback URL to paste into Tencent, Save/Test, the remembered conversations and the recent traffic. ([.docs/im-channels.md](.docs/im-channels.md))
- **Phone access** without a networking project: a Cloudflare quick tunnel (`cloudflared`) publishes the server on an `https://*.trycloudflare.com` address so a phone reaches it without port forwarding or a public IP, and a pairing QR opens the workspace — or the conversation that was on screen — on the other device, with the one-time credential in the URL hash so it never reaches a server log. The tunnel is refused unless the server requires authentication (the address is public), acts only on real `enabled` transitions so an unrelated settings write cannot rotate the address, and stops itself when the backend shuts down. ([.docs/im-channels.md](.docs/im-channels.md))
- **Pi packages** under Settings → Pi Packages: install, list and remove the packages `pi install` understands — `npm:@scope/pkg`, `git:host/user/repo`, and local paths — from the app. Installs go through pi's own package manager, so sources land in the same `settings.json` the CLI reads and a package installed here is visible to `pi list`. The listing reports what each package contributes (skills, prompts, extensions, themes) and where it was installed; new threads load it on their next start, and `/reload` picks it up in an open thread. This is the surface that makes third-party packages like [pi-crew](https://www.npmjs.com/package/@melihmucuk/pi-crew) usable in Peak Code: its six `crew_*` subagent tools, orchestration skill, and `/pi-crew-plan` / `/pi-crew-review` prompt templates all run in-process.
- Themes and prompt-engineering skills ported from [can1357/oh-my-pi](https://github.com/can1357/oh-my-pi) (MIT): `bun scripts/generate-oh-my-pi-theme-seeds.ts` turns oh-my-pi's 100 pi TUI themes into Peak Code `ChromeTheme` seeds (`apps/web/src/theme/oh-my-pi.seed.generated.ts`), selectable in the appearance picker as `omp-*`; and its two prompt-engineering skills (`system-prompts`, `semantic-compression`) ship as a bundled in-tree payload written to the shared skill library at startup, so `read_skill` and `/skill:` resolve them with no network. Both are additive: the skills follow the existing `AGENT_SKILL_PACKS` switch (the same one that governs the default pack, so turning it off drops both), and the themes have no switch of their own — they are extra options in the picker, and not choosing one changes nothing. ([.docs/oh-my-pi-integration.md](.docs/oh-my-pi-integration.md))
- Skills have a per-skill switch, and the ported content has commands. Settings → Skills now carries a toggle on every local skill: switching one off keeps its files on disk but removes it from the agent's per-turn skill list and makes `read_skill` refuse it, so a skill you do not want cannot be listed or opened. It is stored as `AGENT_DISABLED_SKILLS` (empty by default — nothing changes until you use it) and keys on the skill's directory name, the same id `read_skill` resolves. Three composer commands make the ported skills usable without describing them by hand: `/compress` drives `semantic-compression`, `/prompt-review` drives `system-prompts`, and `/review-prs` runs this repository's own gate (`bash scripts/pr-review.sh <PR number|--all|nothing to auto-detect>`, reporting its verdict). All three insert their instruction into the composer for you to read before sending, like `/subagents`. ([.docs/oh-my-pi-integration.md](.docs/oh-my-pi-integration.md))
- Extension failures are reported in the thread instead of being dropped: every extension that fails to load, and every extension handler that throws while a turn runs, now emits a `runtime.warning` naming the extension and the event. Extension load errors were previously invisible unless the model happened to notice a missing tool.

- **Scheduled tasks** (Automations, `/automations`): a plan plus one instruction plus the workspace it runs in. When the plan comes due, the server opens a real thread in that workspace and sends it the instruction, so every run leaves a conversation you can read and continue. Plans are **once**, **daily** and **weekly**, evaluated as wall-clock times in an IANA timezone; a task can be paused, resumed or run by hand, a one-off switches itself off once it has run, and a trigger missed by more than six hours is rolled forward instead of firing late. Each task carries the composer's interaction mode (Agent / Plan / Goal) into its runs. ([.docs/automations.md](.docs/automations.md))
- The `schedule_task` agent tool: "every morning, summarise what changed here" now schedules the task from the conversation itself. It resolves the workspace from the thread it was called in, reports the task id and the next run instant back to the model, and is off in Plan mode. ([.docs/automations.md](.docs/automations.md))
- The engineering workflow is the default for every request, and it is installed rather than assumed. The system prompt now carries a workflow section (DEFINE → PLAN → BUILD → VERIFY → REVIEW → SHIP, with the skill to read at each stage and the judgement call for when a task does not need the process at all) plus the list of the machine's other skills. The `addyosmani/agent-skills` pack backs it — 25 skills, MIT — and the server keeps it installed at the system level through the official CLI (`npx skills add … --global --agent universal`), forked at startup so an offline machine costs a log line and nothing else. Both sections are injected per turn and in every interaction mode, so a fresh thread already has them. ([.docs/skills-and-workflow.md](.docs/skills-and-workflow.md))
- The `kanban_comment` agent tool and the board's standing instructions: a task dispatched from 进行中 now leaves one comment per finished step on its card (what finished, what proved it, what comes next), because conversation text never reaches the board. The card is resolved from the thread the task was dispatched from, so the model cannot aim a comment at another task, and a conversation that is not a board task is told that nothing was written instead of getting a silent success. Off in Plan mode, no approval prompt. ([.docs/skills-and-workflow.md](.docs/skills-and-workflow.md))
- Run modes in the composer: **Agent** (default), **Plan** and **Goal**. The mode travels with the turn and is kept in thread state. Goal mode stores the objective, its acceptance criteria and a token budget, and the harness continues the work across turns (capped by `AGENT_GOAL_MAX_CONTINUATIONS`) until the goal is completed, dropped, or out of budget; the composer's goal panel can pause, resume, complete or drop it. ([#20])
- Model providers under Settings → Model Providers: a provider rail with built-in and custom groups and status dots, an add-provider form with template picker (OpenAI, Anthropic, Google Gemini, OpenRouter, Ollama, DeepSeek, 智谱 AI) and the `ENV_VAR` / `!shell` key hint. ([#19], [#20])
- Add/edit-model dialog: model id, context window (default `1000000`), max output tokens (default `128000`) and input kinds (text, image, video, PDF). Model rows show context/output badges. ([#20])
- Kanban boards, one per project at `.kanban/board.json`: 待开始 / 进行中 / 已完成 / 已阻塞 / 归档 columns with drag and drop, agent dispatch when a task lands in 进行中 or is created there, requirement briefs an agent can draft from the title, and a task detail view that merges board comments with the agent's messages from the thread it ran in — including steer and interrupt for a running turn. ([#20])
- `@peakcode/agent-toolkit`, the agent harness hosted from the server: tools, plans, goals, approvals, skills, runtime paths, their sqlite store, and migration `040_AgentToolkit`. ([#20])
- Settings navigation split (`SettingsNav`, with the skills panel among its sections) and chat activity rows for plan/goal/approval steps. ([#20])

### Changed

- The kanban board reads like a board now rather than a stack of boxes. Every column header and card carries a status glyph (待开始 dashed, 进行中 half-filled, 已完成 checked, 已阻塞 crossed, 归档 struck), and a card shows its work-item code (`PC-29B8`, derived from the task id and the project title), a priority meter, the comment and image counts, the assignee, and how long ago the task moved. The board grew its own left menu — the project switcher plus status / priority / agent-run filters with live counts, each row carrying its own glyph — and a toolbar with a search over titles, requirements and codes, a board↔list switch that renders the same filtered tasks grouped by status, and a "new task" row at the foot of every column. Glyphs, codes, and the priority colours live in one place (`lib/kanbanPresentation`, `components/KanbanPresentation`) that the task page, the create form, and the left menu all draw from, so one task looks the same everywhere. The view mode and menu state persist per browser (`kanbanUiState`), drag-and-drop still resolves its order against the unfiltered column while a filter is on, and column headers keep following the UI language rather than the Chinese names the board file stores.
- The vendored pi SDK moves from `0.74.0` to `0.85.1`, which is what packages built against current pi require (pi-crew needs `>=0.84.3`) and what the `pi` CLI on the same machine already runs. The migration replaces the removed `AuthStorage` + `ModelRegistry.create` pair with the async `ModelRuntime` in the adapter, the provider health probe, git text generation, and the "test connection" probe, and reads completion through the `@earendil-works/pi-ai/compat` entrypoint.
- Extensions no longer need a warning to explain themselves: pi supplies a no-op UI context with `ctx.hasUI === false`, so `ctx.ui.*` calls are inert rather than fatal. The session warning now says that instead of implying extension behavior is unsupported. ([#20])
- The automation model is now Peak Code's own rather than the ported cron shape: plans are once/daily/weekly with a persisted next-run instant instead of five-field cron expressions, a run ends when its conversation reports back (previously a run was recorded as completed the moment its turn was queued), and the run history shows the outcome with a summary and a link into the conversation.
- Scheduling a task from a chat goes through the agent's `schedule_task` tool instead of the client-side keyword interceptor, which used to swallow the message before it reached the model.
- The automations page is rebuilt around the new model: a task description and a workspace picker in the editor, a run history under each task, and react-query polling so scheduled runs appear without a manual reload.
- Documentation covers the new surface: a Scheduled Tasks section in README (English and Chinese) and [.docs/automations.md](.docs/automations.md).
- App identity is unified on `com.peakcode.app` / `com.peakcode.app.dev` across the Electron dev launcher, the Windows AUMID and electron-builder's `appId`, so one app owns its taskbar grouping, shortcuts and notifications. The macOS About panel and the staged installer metadata now read **Peak Code AI**, matching the LICENSE holder. ([#20])
- The server CLI command is `peakcode` instead of `t3`, matching the published bin name. ([#20])
- Documentation covers the new surfaces: README (English and Chinese), `.docs/runtime-modes.md`, `.docs/encyclopedia.md`, `.docs/workspace-layout.md`, `.docs/scripts.md`, and the package tables in `CONTRIBUTING.md`, `CONTRIBUTING.zh.md` and `AGENTS.md`. ([#20])
- [REMOTE.md](REMOTE.md) documents the SSH-tunnel setup for an agent that works on a remote dev box: the server binds its own loopback on the machine that holds the code, `ssh -L` is the only way in, and the browser stays on your laptop.
- Startup no longer runs the user's login shell on every launch. The capture that a GUI-launched process cannot inherit — PATH, `SSH_AUTH_SOCK`, the Homebrew and XDG prefixes — is written to `<baseDir>/userdata/shell-environment.json` by whichever process probes first (the desktop does, before it spawns the backend) and reused while the shell's startup files (`.zshrc`, `.zprofile`, `/etc/paths.d`, …) are unchanged, with a six-hour upper bound because a PATH can also depend on state no file records. On a machine whose `.zshrc` loads a plugin manager that is ~1.1s off every start for both the desktop and the standalone server (measured on the packaged build: ~2.2s → ~1.1s to "Peak Code running"), and an entry that is missing, corrupt, or written by an older version simply falls back to probing.

### Removed

- The automation script columns (`scriptId`, `scriptName`, `scriptCommand`), which no code path ever wrote, and the automation templates that were tied to cron expressions. Migration `041_AutomationSchedules` rebuilds both automation tables; existing cron-based rows are not converted — see [.docs/automations.md](.docs/automations.md).
- The client-side provider-to-provider handoff path: `useThreadHandoff` (called from nowhere), the target-provider list that could only ever be empty now that Pi is the only provider, and the handoff creation, title and model-selection helpers around them. The `thread.handoff.create` command stays on the server, where it is tested and still reads the handoff metadata older threads carry. Threads created before this change keep their handoff badge.

### Fixed

- Unsigned macOS releases are ad-hoc signed instead of shipping with a bundle whose nested code no longer matches its signature, which is the state macOS reports to the user as a _damaged_ download. The signing happens in the build's own `afterPack` hook (`apps/desktop/scripts/electron-builder-after-pack.cjs`) rather than in electron-builder's `mac.sign` hook, because that hook is only reached once electron-builder has found an identity to sign with — exactly what an unsigned release does not have, so a build that configured one still shipped signed-nothing. The bundle is signed inside-out, the computer-use helper keeps the identifier requirement its Accessibility and Screen Recording grants are filed against, and the result is verified before it is packaged; a failure fails the build instead of publishing the artifact. A Developer ID build is untouched and still notarizes as before.
- Desktop packaging (`bun run dist:desktop:*`) no longer fails on bundled `workspace:` dependencies. tsdown inlines every `@peakcode/*` package into the server bundle, so they are skipped when staging the production install. ([#20])
- The release smoke test derives its workspace manifest fixture from the root `workspaces` globs instead of a hardcoded list, so a newly added package can no longer break the release-only steps by being absent from the fixture. ([#20])
- Cached `.electron-runtime` bundles are re-patched when `LAUNCHER_VERSION` changes, and each patched bundle keeps its own metadata file, so Dev and Alpha can no longer validate against the other variant's stale patch. ([#20])
- Saving a model in the provider settings no longer invalidates the `models.json` that pi loads: `video`/`pdf` are stored in a key pi ignores, and cleared fields are dropped from the saved config instead of being written as empty values. ([#20])
